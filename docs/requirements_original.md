# 基于正点原子 Z100 的 CORDIC 正弦波发生、同步 AD 采集与 FFT 频谱分析系统

## 一、项目背景与总体目标

目前我们使用正点原子 Z100 Zynq FPGA 开发平台，希望基于开发板现有的 DA（数模转换）与 AD（模数转换）硬件，开发一套完整的信号发生、同步采集、数据存储和频谱分析系统。

系统使用 Zynq 的 PS（Processing System，ARM 处理器系统）和 PL（Programmable Logic，FPGA 可编程逻辑）协同工作。

本项目的核心目标是：

1. 使用 FPGA 内部的 CORDIC IP 核产生正弦波数字数据。
2. 由 DA 模块将数字正弦波转换成实际模拟信号。
3. 将 DA 输出的模拟信号连接至 AD 输入，构成信号采集回环。
4. PS 能够配置 DA 正弦波的频率、采样点数等参数，并发起一次测量任务。
5. PL 负责精确协调 CORDIC、DA 和 AD 的工作时序。
6. 每次测量时，使正弦波从初始相位 0 开始输出，并尽可能保证 AD 采集的第 0 个有效样本对应正弦波的零点。
7. AD 采集到的数据经过 FPGA 处理和组帧，通过 AXI DMA 写入 DDR。
8. 数据采集完成后，对 DDR 中的采样数据进行 FFT，提取信号的主要频率，并获得完整的幅度频谱。
9. 将结果进行可视化，至少能够展示时域波形、频谱以及实际测得的频率。

这是一个完整的 DA/AD 同步测量实验，也是后续实现雷达实时数据采集、时序控制及 FPGA 数字信号处理的基础。

## 二、总体系统架构

系统分为控制通路、DA 信号发生通路、AD 数据采集通路及数据分析通路。

### 2.1 控制通路

PS（ARM）通过 AXI4-Lite 或现有工程支持的控制接口，向 PL 下发工作参数。

主要参数包括：

- DA 输出频率。
- DA 输出幅度。
- AD 有效采样点数。
- DA 与 AD 的同步延迟补偿参数。
- DMA 目标 DDR 地址和数据长度。
- 启动、停止及复位命令。

PS 负责配置整个系统和监控执行结果，但不通过软件循环逐点控制 DA 或 AD。

PL 需要设计专门的同步控制状态机，以硬件时钟为基础，实现确定性的时序控制。

### 2.2 DA 信号发生通路

PS 配置目标频率 → 相位累加器产生相位数据 → CORDIC Sin/Cos IP 计算正弦值 → 数据格式转换 → DA 驱动接口 → DAC 输出模拟正弦波。

其中，CORDIC 是本项目的正弦波生成核心。

### 2.3 AD 数据采集通路

DA 模拟输出 → 模拟连接 → ADC 模数转换 → PL 数据采集模块 → 数据有效性判断 → AXI4-Stream 组帧 → FIFO → AXI DMA S2MM → PS DDR 控制器 → DDR。

如果所使用的 ADC 是并行输出，采用相应的并行采样逻辑。

如果是 LVDS 输出，则需要增加差分接收、串并转换和数据对齐模块。

必须根据 Z100 实际使用的 ADC 型号及其接口实现，不能直接假设使用之前雷达项目的 AD9228。

### 2.4 数据分析通路

DMA 完成 → PS 获取 DDR 中的采样数据 → FFT 计算 → 提取主要频率及幅度谱 → 绘制时域与频域图像。

第一阶段允许 FFT 在 PS 或 PC 上完成，以优先验证整套系统。

后续如果需要进一步实现 FPGA 硬件加速，可以再将 FFT 迁移至 PL 中的 FFT IP。

## 三、CORDIC 正弦波发生模块

### 3.1 工作原理

CORDIC 本身不是频率发生器，而是依据输入相位计算对应的正弦值或余弦值。

因此，PL 中需要设计一个相位累加器，为 CORDIC 连续提供相位数据。

设：

- \(f_{\mathrm{out}}\)：需要产生的正弦波频率；
- \(f_{\mathrm{update}}\)：DA 数字波形更新频率；
- \(W\)：相位累加器位宽；
- \(\Delta P\)：每次更新的相位增量。

则：

\[
\Delta P=\operatorname{round}\left(\frac{f_{\mathrm{out}}2^W}{f_{\mathrm{update}}}\right)
\]

相位累加器按以下公式更新：

\[
P[n+1]=(P[n]+\Delta P)\bmod 2^W
\]

相位累加器得到的二进制相位值需要转换成 CORDIC IP 所要求的定点数格式。

CORDIC 根据输入相位计算正弦值，然后将结果送至 DAC。

需要检查 CORDIC IP 的相位范围、数据宽度、定点缩放、AXI4-Stream 握手和流水线延迟，不能直接将相位累加器原始数值当作 CORDIC 输入而不做格式适配。

### 3.2 相位同步控制

相位累加器必须具有同步清零或同步重新初始化功能。

每次开始新的测量时：

1. 停止或保持相位累加器在预定状态。
2. 将其相位设置为 0。
3. 按照同步控制信号启动相位累加。
4. 从零相位开始产生正弦波。

对于正弦输出：

\[
y[n]=A\sin(\theta[n])
\]

当初始相位为 0 时：

\[
y[0]=A\sin(0)=0
\]

这里的 0 指数学意义上的零幅值。实际 DAC 可能使用中点码表示零幅值，因此需要根据 DAC 的输出电压范围进行偏置处理。

### 3.3 DA 数据输出

CORDIC 输出需要经过以下处理：

1. 根据 CORDIC 输出格式正确解析定点数。
2. 对输出进行幅度缩放。
3. 根据 DAC 的输入格式转换为对应位宽。
4. 处理有符号数据、偏置和截位。
5. 按 DAC 接口时序输出数据和时钟。

要求生成连续稳定的正弦波，不能因为 PS 端软件处理而使 DA 更新中断。

初期需要能够通过 PS 修改频率，并通过示波器验证实际输出频率。

## 四、DA 与 AD 的同步采集时序

这是整个项目最重要的部分。

### 4.1 核心时序要求

我们希望实现：

**PS 发出一次测量命令后，PL 统一控制 AD 有效采样窗口和 DA 正弦波起始相位，使 AD 的第 0 个有效采样点与 DA 正弦波的零相位对齐。**

需要注意，这里的“AD 开始采集”是指 FPGA 开始记录本次测量的有效样本，不一定意味着 ADC 芯片在该时刻才开始工作。

ADC 可以始终按照采样时钟连续转换，PL 通过采集使能信号决定哪些样本被保存。

### 4.2 为什么不能简单同时启动？

从数字控制角度看，可以在同一个时钟事件中完成：

- 将相位累加器清零。
- 启动 CORDIC 正弦波生成。
- 触发或标记 AD 的有效采集窗口。

但实际硬件中存在延迟：

1. 相位累加器至 CORDIC 的处理延迟。
2. CORDIC 流水线延迟。
3. DAC 数字输入到模拟输出的延迟。
4. 模拟滤波与驱动电路的群延迟。
5. ADC 采样与数字输出之间的流水线延迟。
6. 不同时钟域之间的同步延迟。

因此，不能简单假设同时拉高两个控制信号，就能使第 0 个采样值严格等于 0。

### 4.3 推荐的同步方案

建立一个统一的 PL 同步控制模块 `measurement_fsm`。

PS 只需要下发一次 START 命令。

PL 收到 START 后，按照统一的硬件时序控制相位累加器与 AD 采样窗口。

建议提供以下控制信号：

- `start_req`：PS 发出的测量启动请求。
- `phase_reset`：重置相位累加器。
- `wave_enable`：使能正弦波生成与 DAC 输出。
- `capture_enable`：允许 AD 数据进入当前采集帧。
- `sample_count`：当前有效采样点计数。
- `frame_done`：本次 AD 数据组帧完成。
- `measurement_done`：完整测量任务完成。
- `error_status`：错误状态。

实际启动时序应根据 DAC/ADC 时钟和延迟决定。

建议由一个统一的同步事件作为时间基准，再为 DA 与 AD 分别设置可配置延迟。

需要特别区分：

- DA 侧相位为零的数字时刻。
- DA 模拟输出实际经过零点的时刻。
- ADC 对模拟信号进行采样的时刻。
- ADC 样本最终到达 FPGA 的时刻。

这些时间点不一定相同。

### 4.4 零相位采样目标

希望采样结果满足：

\[
x[0]\approx0
\]

并且：

\[
x[1],x[2],\ldots
\]

能够按照正弦波的预期相位逐渐变化。

但必须考虑：

- ADC 的量化误差。
- DAC 输出零点偏置。
- 模拟噪声。
- 两个转换器之间的相对延迟。
- 模拟滤波器的瞬态与相位响应。

因此不应将“第 0 个 ADC 数值必须严格等于二进制 0”作为唯一验收标准。

更合理的验收要求是：

1. 每次 START 后，DA 均从相同的初始相位生成正弦波。
2. AD 有效采样窗口能够与 DA 相位参考保持确定的相对关系。
3. 第 0 个样本经过必要的零点偏置校正后接近零。
4. 多次重复测量时，波形起始相位具有良好的重复性。
5. 可以通过可配置延迟参数校准同步误差。

若 DAC 与 ADC 使用不同的时钟域，需要设计可靠的同步机制。优先考虑同源时钟或确定性时钟关系。

不能直接将 PS 的异步控制信号接入所有时钟域。

## 五、测量控制状态机

建议采用以下 FSM：

### 状态 1：IDLE

系统处于空闲状态。

等待 PS 发出 START 指令。

此时不应产生新的采集帧，DMA 状态应已经完成初始化或等待 ARM 配置。

### 状态 2：CONFIG

读取并锁存本次测量的参数：

- 目标频率。
- 相位增量。
- 采样点数。
- 同步延迟补偿值。
- 其他必要的采样参数。

参数需要在本次测量期间保持稳定，避免 PS 中途修改寄存器影响当前波形。

### 状态 3：ARMED

确认 DMA 接收通道已经由 PS 正确配置并准备好接收数据。

这里不能只依赖 FPGA 内部的固定等待时间来认定 DMA 已准备完成。

可以由 PS 在成功配置 DMA 后，显式设置一个 `dma_armed` 标志或发出下一阶段启动命令。

### 状态 4：SYNC_START

生成一次统一的同步事件。

控制相位累加器进入初始相位，并按设定时序启动 DA 输出及 AD 有效采样窗口。

### 状态 5：CAPTURE

AD 采集模块接收 ADC 输出的有效数据。

内部计数器记录有效采样数量。

按照规定格式，将数据送至 AXI4-Stream。

这一阶段 DA 持续输出正弦波，AD 持续采集对应的模拟输出信号。

### 状态 6：FRAME_END

达到指定采样点数后，结束当前采集窗口。

最后一拍 AXI4-Stream 数据应携带 `TLAST`。

必须确保 `TLAST` 随最后一个有效数据拍被下游成功接收，不能因为 `TREADY` 拉低而丢失包尾。

### 状态 7：WAIT_DMA

等待 DMA 将剩余数据全部写入 DDR。

注意，AD 采样结束不代表 DDR 写入已经完成。

DMA 完成状态通常由 PS 端驱动或中断确认，并需要检查是否发生传输错误。

### 状态 8：DONE

本次测量任务完成。

PS 可以安全读取已完成写入的 DDR 数据，执行 FFT 并更新界面。

系统准备下一次测量。

同时需要设计超时、复位和错误处理逻辑，避免某个模块异常时状态机永久卡死。

## 六、AD 数据采集与组帧

### 6.1 ADC 数据接收

根据当前硬件使用的 ADC 型号，选择正确的数据接收方式。

需要确认：

- ADC 分辨率。
- ADC 采样时钟。
- 数字输出格式。
- 有符号补码还是偏移二进制。
- 数据有效信号。
- ADC 数字输出延迟。
- 输入电压范围。

如果现有 DA/AD 回环工程已经完成 AD 接收，应优先复用已经验证的模块。

### 6.2 有效采样窗口

建议第一版使用固定长度采样，例如 4096 个样本。

实际数量应支持通过 PS 寄存器修改。

FPGA 使用采样计数器管理当前帧。

只记录处于 `capture_enable` 有效窗口内的 ADC 样本。

如果 ADC 存在流水线延迟，需要确保有效窗口标记与对应的数字采样结果正确对齐。

### 6.3 数据打包

将 ADC 原始数据转换为统一的 AXI4-Stream 数据格式。

例如，若 ADC 原始数据小于 16 位，可以根据有符号格式正确扩展为 16 位。

AXI 数据宽度可结合实际设计选择 16 bit 或 32 bit。

必须明确：

- 每个 AXI 数据拍包含几个 ADC 样本。
- 每个样本的位宽。
- 是否需要符号扩展。
- DDR 中采用什么字节顺序。
- 一个完整采集帧包含多少字节。

建议初期使用简单、固定、明确的数据格式，避免不必要的复杂数据打包。

## 七、AXI DMA 与 DDR 数据存储

### 7.1 数据传输架构

推荐：

AD Capture → AXI4-Stream → FIFO → AXI DMA S2MM → Zynq PS 高性能 AXI 接口 → PS DDR 控制器 → DDR。

其中：

- AD Capture：接收 ADC 采样数据。
- AXI4-Stream：负责流式数据传输。
- FIFO：缓冲数据和处理可能存在的时钟域差异。
- AXI DMA：负责数据搬运。
- DDR：存储本次测量的完整采样帧。

### 7.2 DMA 控制流程

在启动采集前，PS 必须：

1. 初始化 DMA。
2. 确定有效且不会与程序或其他缓冲区冲突的 DDR 地址。
3. 配置 DMA 接收长度。
4. 完成必要的缓存一致性准备。
5. 启动 S2MM 接收。
6. 确认 DMA 接收通路已经准备好。
7. 再允许 PL 启动数据采集。

采集过程中，FPGA 通过 AXI4-Stream 将数据交给 DMA。

接口必须遵守 `TVALID/TREADY` 握手机制。

如果数据生产速度大于 DMA 短时间内的接收能力，需要由 FIFO 进行缓存。

若持续出现 FIFO 满，必须报告异常，不能静默丢弃采样点。

### 7.3 数据完成判定

采样计数达到 N 个后，PL 结束组帧。

但 PS 不能此时立即读取 DDR。

需要等到 DMA 确认传输完成，并检查错误状态。

若 PS 启用了 D-Cache，还需要正确处理 DMA 缓冲区缓存一致性，确保读取的是 DMA 最新写入的数据。

### 7.4 是否需要乒乓存储

第一阶段仅要求一次 START 对应一次采集，因此先采用单缓冲模式。

不必一开始就加入 DDR 乒乓存储，以免增加调试复杂度。

等单次采集、存储与 FFT 均可靠后，再考虑 Buffer A / Buffer B 双缓冲，用于连续采集和实时显示。

## 八、FFT 频率分析与频谱绘制

### 8.1 最终目标

读取 AD 采集得到的 N 个有效采样点：

\[
x[0],x[1],\ldots,x[N-1]
\]

对其进行 FFT：

\[
X[k]=\sum_{n=0}^{N-1}x[n]e^{-j2\pi kn/N}
\]

计算各频率分量的幅度，得到频谱。

### 8.2 频率计算

根据 ADC 采样率 \(f_s\) 和 FFT 点数 \(N\)，频率分辨网格间距为：

\[
\Delta f=\frac{f_s}{N}
\]

从单边幅度谱中寻找主峰，得到峰值索引 \(k_{\max}\)。

初步频率估计为：

\[
f_{\mathrm{measured}}\approx\frac{k_{\max}f_s}{N}
\]

为了提高测频结果的准确性，可以增加：

- 去直流处理。
- Hann 窗等窗函数。
- FFT 峰值插值。
- 噪声抑制。
- 多次测量平均。

需要避免把较强的直流分量或谐波误判为信号基频。

### 8.3 FFT 实现位置

第一阶段：

允许在 ARM 或 PC 上执行 FFT，重点验证 DA、AD、DMA 和 DDR 形成的完整数据链。

如果采用 PC 处理，应明确数据传输方式，例如现有工程是否具备 UART 或 Ethernet 接口，不应假设所有接口都已完成。

第二阶段：

可以使用 Vivado 的 FFT IP，把 FFT 计算迁移到 PL，以提高实时数据处理能力。

初期不要求全部算法都在 PL 中实现。

### 8.4 显示内容

最终需要至少显示：

**时域波形**

- 横坐标：采样时间。
- 纵坐标：ADC 采样幅值。
- 显示完整或局部采集波形。
- 可以放大观察第 0 个采样点以及波形起点是否与零相位对应。

**频域频谱**

- 横坐标：频率，单位 Hz 或 kHz。
- 纵坐标：幅度，可选择线性幅度或 dB。
- 显示 FFT 结果。
- 标记主峰位置。

**频率测量信息**

- DA 设定频率。
- AD 测得频率。
- 频率绝对误差。
- 频率相对误差。

例如：

DA 设定：100 kHz

FFT 测得：100.1 kHz

绝对误差：100 Hz

相对误差：0.1%

上述只是格式示例，不代表实际实验结果。

## 九、Vivado PL 模块规划

建议采用模块化设计，尽量遵循单一职责原则，各模块独立仿真和验证。

推荐模块如下：

| 模块 | 功能 |
|---|---|
| `phase_accumulator` | 相位累加、相位同步复位 |
| `cordic_sincos` | CORDIC 正弦波计算 |
| `dac_driver` | DAC 数据格式与时钟控制 |
| `adc_capture` | ADC 数据接收 |
| `measurement_fsm` | DA/AD 同步时序控制 |
| `capture_packetizer` | 采样计数、组帧、AXI4-Stream 输出 |
| `axi_stream_fifo` | AXI 数据缓冲 |
| `axi_dma` | 数据搬运至 DDR |
| `control_registers` | PS 与 PL 控制寄存器 |
| `debug_ila` | 信号在线调试 |

这些模块名称是建议，并非要求重新开发所有已有功能。

现成的时钟管理、FIFO、AXI DMA、CORDIC 和 DDR 接口应优先使用 Vivado IP。

## 十、PS 软件实现

建议使用 Vitis C/C++ 完成控制程序。

其总体执行逻辑为：

1. 系统初始化。
2. 配置时钟、PL 控制寄存器和 DMA。
3. 用户输入或程序设置目标 DA 频率。
4. 根据目标频率计算相位增量。
5. 配置 DA 输出幅度与采样点数。
6. 配置 DMA 目标 DDR 地址及传输长度。
7. 启动 DMA 接收。
8. 确认 DMA 已准备好。
9. 向 PL 状态机写入 START。
10. 等待一次采集完成，处理超时和异常。
11. 确认 DMA 已完成 DDR 写入。
12. 进行必要的 Cache 一致性处理。
13. 读取 DDR 中的 ADC 原始数据。
14. 使用 FFT 计算主频及频谱。
15. 将数据和结果传送至显示端。
16. 等待下一次测量。

## 十三、开发优先级与验收目标

本项目优先实现**单次触发、单帧采集、单帧测频和显示**。

暂时不强制要求：

- DDR 乒乓存储。
- 连续无间断采集。
- SD 卡持久化存储。
- FPGA 内 FFT 硬件加速。
- 复杂 GUI。
- 多通道雷达目标识别。

这些可以作为第二阶段的扩展功能。

第一阶段最小可用系统应当满足：

**PS 设置 DA 频率 → PS 启动 DMA → PL 同步启动 CORDIC 正弦波和 AD 有效采集 → AD 将指定数量的数据经 DMA 写入 DDR → PS 读取数据 → FFT 获取频率与频谱 → 绘制图像。**

最重要的技术验收点是：

1. DA 能够输出频率可配置的稳定正弦波。
2. CORDIC 相位累加器能够同步归零。
3. PL 能够确定性地协调 DA 输出和 AD 采样。
4. AD 第 0 个有效采样点能够经过时序校准对应正弦波零相位附近。
5. DMA 能够正确将完整采样帧写入 DDR。
6. FFT 能够得到合理的主频及频谱，并与 DA 设定频率进行误差比较。
7. 系统能够重复执行测量，而不需要每次重新配置 FPGA。
