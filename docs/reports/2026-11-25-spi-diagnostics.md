# Z100 与雷达驱控板 SPI 联调报告

**测试日期** 2026-11-25 · **小组** SWU24 级学行班信号处理第三组 · **范围** Z100 XC7Z035 与 ADT6101P 的板间 SPI

## 摘要

- Z100 底板 J6 起初选在 1.8 V，和当前 FPGA 工程的 Bank 11 约束 `LVCMOS33` 不一致。调整至 3.3 V 后，AD24 空载约 3.3 V，连接雷达板时空闲 CS 为 3.29 V。
- 3.3 V 下，分段诊断确认 Z100 能将 CS、SCK、MOSI 送到雷达 MCU，MCU 的 SPI0 能收取测试字，Z100 也能经 MISO 收到 MCU 的回包。
- 诊断固件切换 SPI 模式后存在 TX FIFO 旧字残留。长串压测按延迟对齐后仍出现固定位置的错误，扩大字间等待未消除它。当前条件下尚无旧版实采整帧成功率的有效样本。

## 问题与定位过程

| 阶段 | 实板现象 | 判定 |
| --- | --- | --- |
| 早期接线和启动 | 发现 SCK 和 CS 曾反接。此后部分测试中，接着 SPI 加载位流，雷达 TTL 无回复。断开 SPI 并独立重启后恢复。 | 两个问题可能叠加。回灌、启动 Flash 与排针片选共线均未证实。 |
| 空载电平和跳帽 | AD24 曾在 SPI 断开时测到约 1.8 V。J6 调整后加载 Debug，空载约 3.3 V，接入雷达板时约 3.29 V。 | 已确认原 Bank 档位与 3.3 V 工程不匹配。电平纠正后 SPI 短测打通，但早期所有故障无法单独归因于跳帽。 |
| 实采诊断的复测 | 雷达报 `CAPTURE_READY`。Z100 三次查询返回 `Z100 ERROR SPI_STATUS`，MCU 的 `spi_rx`、`valid`、`bad_crc` 增量为零。 | 该轮未在 MCU 收到请求。还需区分动态波形、片选路径或实采固件的接收行为。 |
| GPIO 与硬件 SPI 分段 | 5/5 轮在 MCU GPIO 看到 4 个片选窗口和 64 个有效 SCK 上升沿，MOSI 解析和硬件 SPI0 所收的四字均正确。MCU 用 GPIO 驱动 MISO 低、高，Z100 分别读到全零、全一。 | 当前诊断配置验证了两个方向。第一轮硬件实际回包正确，后四轮首字和顺序错位。 |

## 复现的两个问题

1. **模式切换后 TX FIFO 残留。** 单次四字测试中，MCU 开始时放入标记 `5AA5`，每读一字再把反码入队。上一轮最后发 `00FF` 时，对应反码 `FF00` 没有被额外的时钟读走。重启 SPI 模式后，第二轮回包从 `FF00 5AA5 5A3C C3A5` 开始。连续和反复切换记录也能看到前轮数据。实测指向这版诊断固件的发送队列管理。 [首轮](../../evidence/spi_diagnostics_20261125/board_20261125_215536/result.json) · [第二轮](../../evidence/spi_diagnostics_20261125/board_20261125_215700/result.json) · [连续与切换](../../evidence/spi_diagnostics_20261125/fifo_continuous_20261125_220656/result.json)
2. **长串的固定位置错字。** 额外字间隔设为 0、100、300、1500 µs，每档两轮、每轮 256 字。MCU 共计数 2,048 字且无 RX 溢出。考虑每轮 8 字回包延迟，两组试验各跳过首次突发的前 16 字，2,016 个可比较字中有 24 个差异。八轮的零基回包索引都为 **66、195、210**。拆成短组时，相关字的 MCU GPIO 与 SPI0 接收均正确，短组回包对齐后 40/40 字正确。长串中的差异究竟首先出现在 MCU RX、TX 入队、还是 Z100 RX，仍待同轮完整记录验证。 [0/100 µs](../../evidence/spi_diagnostics_20261125/stress_20261125_221133/result.json) · [300/1500 µs](../../evidence/spi_diagnostics_20261125/stress_20261125_221704/result.json) · [短组回测](../../evidence/spi_diagnostics_20261125/target_replies_20261125_221555/result.json)

| 零基回包索引 | 预期 | 实测 |
|---:|---|---|
| 66 | `5816` | `58EF` |
| 195 | `C1A7` | `C180` |
| 210 | `F1A6` | `F184` 或 `F180` |

历史旧版每帧 47,136 字节，需读取 737 块并全部通过分块 CRC16，单块失败会中止该帧。现有长串错字重复出现在固定位置，旧程序与测试的帧结构和发送时序也不同，因此不能把字级通过率乘到整帧。工程判断是**短握手值得复测，稳定整帧仍有风险**。 [旧版四线 SPI Release](https://github.com/WuWingKit/z100-ad9280-capture/releases/tag/v0.7.0-spi-four-wire-20261119)

## 程序修复与回归

1. **先定位首次差异。** 给同一轮 256 字的 Z100 TX、MCU RX、MCU TX FIFO 实际入队和 Z100 RX 加统一索引。MCU 在 RAM 记录，测试结束再经 TTL 导出，避免 UART 日志改变字间时序。
2. **修复 MCU 发送队列。** 模式切换前确认移位已结束。采用芯片手册支持的外设复位或经过实测的排空方案。明确事务起始、填充词数量和字边界，避免静默保留上一事务回包。8 字延迟是本次观测值，不能写死为通用协议规则。
3. **完善 Z100 收帧。** 响应头、请求 ID、操作码、偏移、长度及 CRC 联合校验。只对同一帧同一偏移的读取块作有限重试，触发重试应保留同一请求 ID。整帧的分块 CRC、长度和序号通过后再 ACK。记录首次失败偏移和重试次数。
4. **按证据调整波形。** 若 MCU RX 与入队值都正确，再对照 MCU 端和 Z100 端的 CS/SCK/MISO，检查实际 SCK 分频、取样边沿与建立时间。若 MCU RX 先出错，优先查看 MOSI 与 SPI0 接收时序。
5. **同条件回归实采。** 先用旧版原样冷启动并读 30 帧，记录握手、首块、完整帧的通过数。修订后跨多次上电复测至少 100 帧，按帧长、737 块 CRC16、帧头、序号及 ACK 判定。雷达目标探测另外用实物目标做对比。
