# Z100与雷达MCU：接线及Debug操作

更新：2026-11-12。开发板XC7Z035FFG900-2，Vivado/SDK 2018.3，Keil ARM Compiler 5.06u7 build960。

## 一、先识别两个处理器

- 雷达MCU：老师参考工程所在的ADT6101P/ADT2011前端，用Keil和J-Link/SWD调试。
- Z100：PL接收SPI、PS控制DMA和UART，用Vivado/SDK和JTAG调试。
- 传输方向：FPGA发SYNC；MCU是SPI主机，发SCLK/CS/MOSI；MCU另发READY确认。FPGA是SPI从机。
- 本版没有开机自动SYNC或自动采集。MCU等待外部上升沿，Z100等待串口命令。

## 二、接线表

Z100的J37当前空闲（用户已确认）。依据正点原子底板原理图PDF第19页、核心板Bank11管脚表选择：

| 信号 | 雷达MCU | Z100封装脚/Bank | J37针号 | 方向 |
|---|---|---|---|---|
| SPI SCLK | P3，SPI0 CLK | AC24 / Bank11 | 31 | MCU→FPGA |
| SPI CS低有效 | P0，原TX0 | AD24 / Bank11 | 29 | MCU→FPGA |
| SPI MOSI | P6，SPI0 MOSI | AG24 / Bank11 | 32 | MCU→FPGA |
| SYNC | P1，原RX0，GPIO上升沿输入 | AG25 / Bank11 | 30 | FPGA→MCU |
| READY | P12，GPIO输出 | AA24 / Bank11 | 27 | MCU→FPGA |
| GND | 雷达板GND | GND | 2或4 | 共地 |

J37-1是+5V，J37-3是VCC_B10，均不作为本方案信号线或跨板供电线。J37-28是普通IO，**不是GND**。以板上的1脚标记和AC24/AG24等丝印确定方向，不按照片左右猜针号。

两块板分别正常供电，只连接上表五根信号和地。XDC采用LVCMOS33；接线前核对实际Bank11和MCU IO均为3.3V，不能把5V接入IO。先断电接线；短线连接、靠近信号布地，12.5MHz不能用长而凌乱的飞线作为最终方案。

雷达板拆除原UART0的TX0/RX0与底板USB-UART之间的跳线帽，尤其P1/RX0不能再由USB-UART的TX驱动。P0由SPI片选独占，P1由SYNC输入独占。SPI的P3/SCLK不要和I2C的SCL混淆，按P3逻辑引脚核对。

P4保持高，禁止选中板载启动Flash。MISO/P5不连接Z100。P19启动选择以及SWD引脚保持原用途。

## 三、先用MCU自检版验证链路

1. 打开 `mcu_frontend/05_application/firmware_app/keil_project/firmware_app.uvprojx`。
2. 选择 **radar_sync_selftest**，重新编译。不要选真实采集版做第一次链路检查。
3. Options for Target → Debug → J-Link/J-TRACE Cortex；Settings中Port选择SW，初次使用1MHz，稳定后可参考Quick Start提高至5MHz。
4. 按Quick Start第5页将P19配置为RAM启动；J-Link连接SWDIO、SWCLK、GND和目标电压参考。J-Link目标电压参考不是跨板供电接口。
5. Flash Download设置Do not Erase；RAM for Algorithm起点0x20000000、大小0x1000；Programming Algorithm列表清空。本流程只调试RAM程序，不烧写外部Flash。
6. Debug勾选Load Application at Startup及Run to main，进入Debug后在main暂停。继续运行到主循环，再开始Z100侧命令。
7. 观察 `g_radarSync`、`g_radarLastResult`、`g_radarCompletedEvents`。初始化后READY应为高，尚未有采集事件，previous=-1。

Quick Start文件名为ADT6101P，但正文标注ADT3102；用户确认实际底板与图一致。本工程的寄存器、SPI/GPIO配置仍以现有ADT6101P HAL为依据，没有把另一个型号的寄存器地址直接套过来。

自检版只在RAM生成固定格式的样本，不调用采集/RF开启回调，也不执行ADT2011波束初始化；它仍使用真实GPIO、SPI和A/B缓冲区。模拟样本不得作为雷达测量结果。

## 四、启动Z100的PS Debug

1. Z100上电，连接JTAG和**PS端USB串口**。串口115200、8N1。连接哪个COM以系统枚举为准。
2. SDK打开工作区 `E:/FPGAWork/radar_sync_sdk_20261111`。硬件平台为radar_hw，应用radar_uart。
3. Xilinx → Program FPGA，Bitstream选择本工程 `hardware/radar_sync.bit`。使用本版配套的 `radar_sync.hdf`，不要混用旧ADC工程的bit。
4. Debug Configurations → Xilinx C/C++ application (System Debugger)，Processor选ps7_cortexa9_0，应用选择radar_uart/Debug/radar_uart.elf，也可浏览本工程 `hardware/radar_uart.elf`。
5. 开启PS初始化，使用该硬件平台生成的ps7_init.tcl初始化DDR和FCLK；进入Debug停在main后，Resume/F8运行。
6. 串口应出现 `Z100 RADAR EXTERNAL SPI + SYNC`。如果只有FPGA配置完成而没有此文本，PS应用还未运行或串口选择不正确。

串口助手与SDK Terminal不能同时占用同一个端口。旧AD/DA网页使用m/t命令，不适用于本版p/c协议。

## 五、单次命令顺序

每条命令后发送真实回车，ASCII的字符串`\r`不是回车。HEX发送可直接使用下表。

| 步骤 | ASCII | HEX | 预期 |
|---|---|---|---|
| 读状态 | s | 73 0D | mcu_ready=1、ready=1、primed=0 |
| 第一次SYNC | p | 70 0D | MCU READY先低再高；只采A、不发送SPI；PS打印PRIME ACK |
| 接上一帧 | c | 63 0D | 先武装DMA，再SYNC；采B发A；DDR得到47136B，seq=0 |
| 检查自检样本 | v | 76 0D | LINK SELFTEST，11776个复数点，errors=0、PASS |
| 再采一次 | c | 63 0D | 采A发B，seq=1；再发v应PASS |
| 导出完整帧 | d | 64 0D | BEGIN RADAR_RAW…END RADAR_RAW，全部47136B |
| FPGA软复位 | r | 72 0D | 仅复位FPGA/DMA；重新prime之前也必须重置MCU会话 |

每次c会先由PS配置DMA接收长度和DDR地址，再产生SYNC；收到完整帧后校验头、长度和保护区，确认DDR完成后ACK。最后一个AXIS字握手不等于DDR写完，二者都要成立。

`d`采用HEX文本，115200波特率导出整帧约十多秒，因此不是连续高速雷达数据流。保存纯接收文本后可运行：

```powershell
python scripts/export_uart_frame.py uart_capture.txt --out captures/run1
```

输出bin、元信息JSON和I/Q CSV。CSV同时给原始无符号容器值及16位补码解释，没有做电压或相位标定。

## 六、切换真实采集版

1. 停止发送新命令，确保SPI CS高。
2. Keil选择 **radar_sync_mcu**，重新编译、进入Debug并运行。它会初始化ADT2011，但不会自动开始采集。
3. 重置Z100的PS/FPGA会话，等待MCU READY=1，再执行s→p→c。
4. 真实回波用c检查长度/头/保护区，用d导出。**不要以v作为真实雷达通过标准**，真实ADC值不会匹配自检RAM图案。
5. 首先固定0°波束。链路稳定后，把 `project_config.h` 中PROJECT_SYNC_SCAN_ENABLE改为1并重编译，才轮转19个波束。

## 七、断点与复位注意事项

- MCU在SYNC ISR、ADC等待或SPI发送中停住，FPGA可能超时，这是预期现象。先停止请求，恢复/复位两端，再重新prime。
- FPGA的r不能清空MCU A/B缓冲状态。只复位一端后直接p会造成“首次预填充却返回旧帧”的协议错误。
- Keil中优先在空闲主循环打断点，先读READY再决定是否开始事务。
- MCU故障后READY保持低；Keil查看g_radarSync.fault、rejected_sync和g_radarLastResult。不要反复发SYNC掩盖故障。
- PS状态error=1时保留raw状态和fault_code；正常数据统计的本地CRC不等于源端载荷CRC。
