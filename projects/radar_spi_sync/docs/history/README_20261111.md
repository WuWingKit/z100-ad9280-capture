# 相控阵前端 SPI + SYNC 接收开发副本

日期：2026-11-11。器件：XC7Z035FFG900-2；工具：Vivado / SDK 2018.3。

本目录是新的独立工程，基于原来的 Z100 SPI→FIFO→DMA→DDR 工程扩展。老师的 MCU 原工程和此前通过测试的 8 字节工程均保留。目标是让 FPGA 发出 SYNC，由雷达 MCU 响应上升沿，采集本轮数据并发送上一轮结果；FPGA 接收完整帧并保存到 DDR。

当前逻辑仿真、两帧全长DDR集成检查、MCU可移植C测试、PS程序编译和完整Vivado综合均通过。详细验证范围见 `docs/VALIDATION.md`；综合后仍有估计Hold违例，未完成实现后时序收敛。

**目前是开发及仿真版本。SYNC/SPI 实际引脚、电平未确定，不能直接上板下载。没有生成本版 bit 文件。** MCU 目录提供可移植调度模块，尚未绑定具体 GPIO 中断及老师工程硬件函数，不能当成已完成的雷达固件。

在 Vivado 中 File → Open Project，选本目录 `radar_sync.xpr`，再点 Open Block Design。这里的 SPI 角色与之前的 PS 模拟从机实验不同：**雷达 MCU 是 SPI 主机；FPGA 是 SPI 从机，同时 FPGA 是 SYNC 发起方。**

## 数据与控制链路

```text
PS 串口命令 → AXI GPIO → FPGA SYNC 输出 → MCU 上升沿事件
                                            │
                本轮 ADC DMA→A/B另一缓冲区←──┘
                完成采集、关闭RF、封装本轮帧头
                                            │
                上一缓冲区完整帧 → MCU SPI主机
                                            ↓
FPGA SPI接收 → 整帧BRAM暂存及校验 → 32bit FIFO
      → AXI Stream → AXI DMA S2MM → HP0 → PS DDR
      → PS 检查DMA完成及帧头 → ACK → 允许下一次SYNC
```

帧头和对应雷达数据一起进入同一个 A/B 缓冲区。发送时不根据“当前波束”临时重建头部。首次 SYNC 只填 A，第二次采 B 发 A，第三次采 A 发 B。波束索引、角度和序号属于采集时刻，因此不会因发送滞后一轮而错配。参考硬件当前要求先完成 ADC、关闭 RF 后再 SPI 发送；本版没有宣称 ADC 与 SPI 同时进行。

每帧为 **47136 字节**：32 字节帧头 + 23 chirp × 512 点 × 4 字节 I/Q。实际采集24 chirp，第一 chirp 不发送。SPI 使用 Mode 0、16bit、MSB先发，目标12.5MHz。帧内CS保持低，发完全部23568个16bit字后拉高。此时 FPGA 才决定是否允许进入 DMA；不再沿用此前“CS=1MHz、每帧1字节”的模拟协议。

## 手动运行与命令

本版没有自动周期 SYNC；PS 程序在每个命令后等待回车。UART0，115200，8N1。PS程序不负责生成模拟SPI数据。

| 命令 | 功能 |
|---|---|
| `p` + 回车 | 首次预填充SYNC；不启动DMA，不应有SPI帧 |
| `c` + 回车 | 先武装47136B DMA，再发SYNC，接收上一轮完整帧并检查DDR结果 |
| `s` + 回车 | 读取状态/错误码 |
| `d` + 回车 | 手动输出上一有效帧的原始HEX，串口较慢 |
| `r` / `q` + 回车 | 复位FPGA协议和DMA；不会复位MCU，请同时重置MCU会话再预填充 |

PS 限制相邻 SYNC 至少50ms。默认 SYNC 高电平10µs，预填充等待50ms、接收/流转超时200ms。首次等待是定时保护，**不是MCU真实完成反馈**；真实采集耗时超过50ms时必须增加等待，或增加MCU-ready握手。

目前本版不接旧网页的 `m/t` 8字节协议，也没有给47136B雷达帧做新的FFT/波束绘图；本次工作范围为采集调度、帧关联、接收和DDR存储。

## 重现验证

在本目录 PowerShell 中运行（本机安装位置如下）：

```powershell
$env:PROCESSOR_ARCHITECTURE='AMD64'
& 'E:/Xilinx/Vivado/2018.3/bin/vivado.bat' -mode batch -source scripts/run_unit.tcl
& 'E:/Xilinx/Vivado/2018.3/bin/vivado.bat' -mode batch -source scripts/run_ddr.tcl
& 'E:/Xilinx/Vivado/2018.3/bin/vivado.bat' -mode batch -source scripts/synthesis.tcl
& 'E:/Xilinx/SDK/2018.3/bin/xsct.bat' scripts/build_software.tcl
```

按顺序运行，不能同时让两个 Vivado 进程修改同一主工程。`run_unit.tcl` 使用单独的测试工程；`run_ddr.tcl` 切换主工程仿真顶层为 `tb_radar_ddr`。在GUI点 Run Behavioral Simulation 可运行集成仿真，波形中重点看 `radar_sync`、`spi_cs_n`、`spi_sclk`、接收计数、状态、FIFO写使能、AXIS握手/TLAST、DMA状态。

软件构建工作区放在 `E:/FPGAWork/radar_sync_sdk_20261111`，原因是 SDK 2018.3 在含空格路径下启动 Eclipse 存在路径截断；主硬件工程仍在本目录，ELF会复制到 `hardware/radar_uart.elf`。首次构建后可直接在该 SDK workspace 编译，重复创建项目脚本前不要覆盖自己的修改。

仅修改本目录 `software/main.c` 后，用 `xsct.bat scripts/rebuild_software.tcl` 更新并重新编译已有应用。该脚本会把本目录源文件覆盖到生成的SDK应用，请在本目录维护正式源码。硬件地址/外设配置发生变化后还需在SDK更新硬件平台和BSP。

`scripts/create_project.tcl` 是从 `seed/` 重建新工程的脚本，供空目录重建；不是每次打开都要运行。日常直接打开 xpr。

验证分为三个层次：

- `tb_radar_sync`：真实异步SPI信号→接收器→解析/缓存→FIFO模型→AXIS；使用缩小帧参数验证MCU行为模型、错误帧、乒乓关联及反压。
- `tb_radar_ddr`：实际47136B帧→真实BD中的缓存/FIFO/DMA/HP0/PS DDR模型，逐字节检查两帧及边界保护。默认在SPI解码输出边界注入16bit字，以减少PS7 VIP仿真耗时，**不是全长真实SPI线级端到端测试**。将该TB的 `WIRE_MODE=1` 可运行完整SPI线级模式，但每帧约30ms模拟时间，耗时很长；该模式试运行日志不能作为完成证明。
- `sim/test_mcu_pipeline.c`：执行实际可移植MCU C模块，用硬件回调替身检查缓冲区所有权、上一帧头/载荷、忙时ISR拒绝和发送失败锁定。`scripts/test_mcu_host.cmd` 使用本机VS2022运行；另有Cortex-M3 C99严格语法检查。两者均不验证真实MCU寄存器与中断时延。

结果以 `evidence/*result.txt`、综合报告和构建日志为准。MCU行为模型不执行真实ARM固件；Vivado仿真成功不能替代外部接线、真实MCU中断与RF时序测试。帧头XOR只校验头部，载荷没有线上CRC；PS输出的local_payload_crc仅供留存，不能独立证明真实雷达载荷无误。
