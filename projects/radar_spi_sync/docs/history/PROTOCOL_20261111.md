# SYNC、帧关联与寄存器定义

## 1. 一拍延迟指什么

```text
SYNC0: 采集 seq0 / beam9 → A头+数据；不发送
SYNC1: 采集 seq1 / beam10 → B头+数据；发送 A(seq0 / beam9)
SYNC2: 采集 seq2 / beam11 → A头+数据；发送 B(seq1 / beam10)
```

扫描关闭时所有帧beam9=0°；扫描打开后才轮转19个索引。seq从0开始，16位回卷。帧头必须从该缓冲区的采集快照填写，而不是从发送时的全局变量读取。

MCU缓冲区状态：FREE→CAPTURING→READY→SENDING→FREE。ADC写当前空闲区；SPI只读上一READY区；实际SPI Busy清零、CS拉高后才释放。第一个SYNC无上一帧。处理中再来SYNC只记拒绝次数，不覆盖缓冲区。

雷达RAM基址A=0x20008000，B=0x20014000，各49152B。采集24×512×4B；发送起点=基址+2016，先32B头，接后23个chirp。填头发生在ADC DMA完成之后；不会让ADC覆盖有效头。

FPGA状态：IDLE→PRIME→IDLE；正常IDLE→RECEIVE→FETCH/PUT→DRAIN→WAIT_ACK→IDLE。异常进入FAULT，整帧校验未通过时不送DMA。WAIT_ACK无接收超时，允许PS在调试断点处暂停；MCU在此阶段应保持SPI空闲。

## 2. SPI帧头（每项16bit）

| Word | 内容 |
|---|---|
| 0 | magic=0xA610 |
| 1 | version=3；兼容接收version2 |
| 2 | 头部16个word |
| 3 | 采集时beam index，0..18 |
| 4 | 采集时角度，int16，单位0.01°；-4500+index×500 |
| 5 | 总波束19 |
| 6 | 每chirp512点 |
| 7 | 有效23 chirp |
| 8 | 采集24 chirp |
| 9 | 每点4B，I/Q的具体符号解释仍以雷达ADC定义为准 |
| 10/11 | 分辨率µm，低16/高16；当前1400MHz配置快照 |
| 12 | 全帧47136B |
| 13 | 头部32B |
| 14 | v3:采集序号；v2:保留0 |
| 15 | Word0..14的逐字XOR |

SPI每个word按高bit先发。FPGA每两个word组成32bit `{second_word,first_word}`，DDR中每个16bit字段低字节在前。例：0xA610在DDR是`10 A6`；不能把串行MSB先发等同于DDR大端存储。

Version3是本次两端协议扩展，不是老师原始版本。第一帧建立seq基准，后续检查+1；v2没有可靠seq字段，不能用它证明不丢帧。线上没有payload CRC；头部XOR不是载荷校验。

FPGA接收先缓存整个47136B，检查魔数/版本/波束角度/长度/XOR/序号/完整字边界，CS拉高且长度正确后才放行。需要约47KB片内缓存；FIFO仅作流转缓冲，不能拿原1024×32bit FIFO直接容纳整帧。

## 3. GPIO控制

| 地址 | 用途 |
|---|---|
| 0x41200000 | command（PS写） |
| 0x41200008 | status（PS读） |
| 0x41210000 | prime_wait_cycles，100MHz时钟周期，0用默认5000000 |
| 0x41210008 | timeout_cycles，100MHz时钟周期，0用默认20000000 |

command：bit0请求翻转位；bit1=1表示首次prime；bit2软复位高有效；bit3=1表示PS已武装DMA；bit4为DDR完成ACK翻转位。配置在事务开始前写好并保持稳定。bit3是PS软件承诺，不是硬件自动侦测DMA状态。

status：bit0忙；bit1错误；bit2完整帧有效；bit3已处理的请求翻转位；bit4拒绝请求；bit5心跳；bit6可请求；bit7prime定时结束；bit23:8为收到的16bit字数；bit27:24状态；bit28实际最后AXIS字握手；bit29回显DMAarmed；bit30回显prime；bit31=0。

FAULT时bit23:8改为`{error_code, word_count[7:0]}`，不能再当完整字数读。错误码：01非法空闲请求；02头部错误；04seq不连续；08超长；10短帧/非完整16bit/缺有效头；20接收窗口外出现CS；40接收或流转超时。错误码不是位掩码累加，仅报告最后锁存的原因。

DMA基址0x40400000；S2MM控制+0x30、状态+0x34、目的地址+0x48、长度+0x58。长度寄存器已从14扩展至16位，支持47136B。每帧11784次32bit握手，最后一次TLAST；TKEEP=0xF；反压时数据/TLAST保持稳定。

## 4. 时钟、接线与运行限制

PS FCLK_CLK0=100MHz驱动PL。SPI输入经3级同步并在系统域检测SCLK上升沿，Mode0、16bit、12.5MHz；MOSI应在下降沿更新并满足下一上升沿附近稳定。仿真还使用非整数相位关系验证异步采样。此方法不是MMCM锁相，不能任意提高SPI频率；外部时序与板级延迟须接线后验证。

| FPGA方向 | 信号 | 物理引脚 |
|---|---|---|
| 输出 | radar_sync | 待定，连接MCU上升沿GPIO |
| 输入 | spi_sclk | 待定，雷达MCU SPI时钟 |
| 输入 | spi_cs_n | 待定，雷达MCU帧选通 |
| 输入 | spi_mosi | 待定，雷达MCU数据 |

没有MISO返回数据，也没有真实MCU-ready线。默认10µs SYNC脉冲、50ms间隔，不能由软件打印“ready”推断MCU已经采完。若MCU忙或异常，应停止SYNC并复位两端协议，不能单独复位FPGA后直接继续prime。

对源端的首次配置、采集完毕、RF关闭、发送实际结束分别做清楚后，再将定时prime替换为必要的硬件握手，是后续真实联调重点。
