# 从SYNC到DDR：代码逐段说明

源码新增注释采用ASCII英文，避免Keil 5与Vivado 2018.3混合编码导致乱码。本说明按执行顺序用中文解释；厂商原版权和驱动注释保留。

## 1. MCU启动：main.c

文件在`mcu_frontend/05_application/firmware_app/source/src/main.c`。

启动流程为：中断向量表设到0x8000→芯片时钟/ADC初始化→绑定原有雷达硬件回调→初始化毫秒计时→真实版本初始化ADT2011→AppSyncFrontend_Init→循环AppSyncFrontend_Process。

旧AppFrontend_RunCycle自动50ms采集已禁用；程序不会在第一次SYNC前偷偷采集一帧。旧采集完成函数不再写P0/P1，避免把SPI片选拉低或把SYNC输入改成输出。

Keil有两个目标：radar_sync_mcu使用真实ADC和相移器；radar_sync_selftest在RAM生成固定数据，不调用采集/RF开启回调。两者的SPI格式、缓冲区及触发流程相同。

## 2. 板级绑定：app_sync_frontend.c

该文件把通用乒乓逻辑与老师已有的雷达驱动连起来：

| 通用回调 | 板级实现 |
|---|---|
| set_initial_beam | adt_scan_set_beam，初始9=0° |
| capture_start | adt_scan_acquire_start，传本轮A/B地址 |
| capture_finish | adt_scan_acquire_wait，确认ADC DMA结束、关闭RF |
| wait_us | 原delayUs |
| prepare_beam / load_beam | 原相移器预写及LOAD函数 |
| send_frame | AppSpiStream_Prepare→Trigger→Wait；失败Abort |
| write_word | 把16位帧头写入指定RAM地址 |
| enter/leave_critical | 保存/恢复PRIMASK，短暂关中断完成事件交接 |

SPI配置Mode0、16bit、MSB先发；FRAME_LOWPOWER=1时本地sys_bsp给出APB=50MHz，显式SCR=0、CPSR=4，目标12.5MHz。若getPclk不是50MHz就不宣告READY，避免时钟配置与采样能力不符。

GPIO中断只做三件事：读/清P1事件、READY拉低、调用RadarSync_OnRisingEdge记录pending。所有ADC等待、波束寄存器传输、SPI循环都放在主循环。

READY使用实际底板可见的P12。主循环只在没有pending、busy和fault时拉高READY；最后一次状态检查在短临界区内，避免ISR刚记录新事件，主循环却错误拉高READY。

## 3. 乒乓状态机：mcu_sync/radar_sync_pipeline.c

通用模块是Keil工程直接引用的同一个源文件，不是另复制一份。主机C测试也执行此文件。

每个缓冲区保存base、seq、beam、angle、resolution和state。状态变化为FREE→CAPTURING→READY→SENDING→FREE，异常标BAD并锁住整个会话。

一次Process的顺序：

1. 原子取走ISR的pending，设busy，选择上一缓冲区的另一块作为采集区。
2. 在启动ADC前把当前已LOAD波束、序号和配置写入该缓冲区的描述符。
3. ADC启动→等待100µs→预写下一波束→等ADC DMA结束并关闭RF→LOAD下一波束。
4. 此时才填写本轮帧头，避免ADC覆盖元信息。
5. 若存在上一轮READY缓冲区，发送它的头和数据，真正等SPI Busy清零、CS拉高后才释放。
6. 当前采集区成为下一次要发送的previous。首次只填A，返回1；之后采另一块并发上一块，返回2。

这符合参考工程“先采集并关闭RF，再发送SPI”的时序。**没有声称ADC与SPI物理并发**，乒乓的意义在于所有权、上一帧稳定数据和正确的波束关联。

## 4. 为什么帧头不会跟错波束

seal_header读取的是该缓冲区描述符中的beam/seq，不是已经切换到下一轮的全局波束变量。Version3的Word14为采集序号，Word15是头部XOR16。

示例：SYNC0采seq0、beam9存A；SYNC1采seq1、beam10存B并发A，发出的头仍然是seq0、beam9，而不是beam10。

帧头放在第一个chirp末尾32B（偏移2016），随后是后23个chirp的47104B数据。整帧47136B；第一个chirp的采样不发送。

## 5. SPI发送不是MCU侧SPI DMA

`app_spi_stream.c`由CPU轮询TX FIFO空位，按顺序写23568个16bit字。CS跨整个帧保持低，Wait确认Busy清零才拉高。代码中保留的DMA清理接口不代表发送已由DMA完成。

ADC→MCU RAM用ADC DMA；FPGA AXIS→PS DDR用AXI DMA。这三者不能混为一谈。

## 6. FPGA接收：spi_slave_rx16.v

外部SCLK、CS、MOSI分别经三级ASYNC_REG同步到FCLK0=100MHz。SCLK当普通输入数据检测上升沿，不使用它驱动PL时钟网络。

CS下降清空16bit移位寄存器；CS低且检测到SCLK上升沿时移入MOSI；收到16bit后发一个周期word_valid。CS上升时发frame_end；若不足16bit则标partial_word。

协议允许字与字之间停钟，依靠CS分帧。它不再是早期“每个CS只接1字节”的模拟协议。

## 7. FPGA调度与整帧缓存：radar_frame_capture.v

PS通过AXI GPIO翻转request位。核心先检查空闲、CS高和MCU READY，正常采集还要求已prime且PS已武装DMA，然后输出10µs SYNC。

首次PRIME要求READY从高变低再变高，证明MCU响应并结束首轮。prime_wait_cycles现在是最大等待时间，不再是到时自动当作成功。

正常帧先全部进入BRAM。验证魔数、版本、波束范围/角度、固定布局、头XOR、长度和版本3序号连续性。只有CS上升且检查全部通过，才放行到FIFO。坏帧不会先污染DMA。

RAM独立使用同步读写模板；控制和RAM地址寄存器使用同步复位，避免异步复位直接改变BRAM地址引发REQP-1839。缓冲RAM本身不清零，完整新帧覆盖后才读取。19个波束角度使用常量表，避免组合乘法占用DSP。

忙时新请求只记拒绝，不能跳过原事务同周期的SPI字。故障进入FAULT，不自动继续猜测下一帧边界。

## 8. FIFO与AXIS：radar_fifo_to_axis.v

FIFO是32bit读写、FWFT。TVALID来自FIFO非空；只有TVALID且TREADY握手成功才读FIFO、增加字计数。反压期间TDATA/TLAST保持不变。

每帧11784个32bit字，TKEEP=0xF，最后一个字TLAST=1。stream_done表示最后一次AXIS握手，并不表示DDR物理写入已完成。

## 9. BD和PS：software/main.c

控制路径为PS M_AXI_GP0→AXI Interconnect→GPIO和DMA寄存器。数据路径为AXIS→DMA S2MM→SmartConnect→PS S_AXI_HP0→DDR。DMA长度位宽16，能够接收47136B。

PS按c命令清/刷缓存并武装DMA，再发SYNC。之后同时等待DMA完成及stream_done，失效CPU缓存后检查帧头、收到的字数和保护区，再翻转ACK允许下一轮。

缓存维护很重要：HP0不是CPU缓存一致性端口，必须在DMA前flush、完成后invalidate，不能把CPU缓存里的旧值当成新采样。

`v`只检查自检固件的确定性RAM数据；`d`导出整帧，`export_uart_frame.py`可离线转换成bin/JSON/CSV。真实雷达样本的本地CRC仅用于留存，没有源端载荷CRC可供独立比对。
