# SPI四线主从链路上板自检报告

日期：2026-11-19。FPGA主机、区控板MCU从机；仅SPI四线与GND，无TX/RX握手。用户已烧录MCU自检版并接线。本次仅通过JTAG下载Z100 bit和PS ELF，未写任何Flash。

## 已执行
1. JTAG加载spi_only_master.bit与spi_only_ps.elf，启动横幅匹配。
2. 下载脚本首次STATUS成功；随后连续5次STATUS全部返回flags=0000、busy=0、frame=0、fault=0。
3. SPI TRIGGER首次采集完成，返回SPI PRIME COMPLETE，第一次没有上一帧，不读帧。
4. 连续三次TRIGGER，STATUS等待、64字节分块读取上一帧、CRC16校验、ACK释放缓存、UART完整导出。
5. PC逐点对照MCU固定模式，验证全部I/Q和帧头/序号，不只检查返回的PASS文本。
6. 重复p被PS拒绝；随后STATUS仍为flags=0000，证明该防重复操作未改变SPI会话。

## 可以证明与不能证明
本次验证了真实区控板SPI从机响应、FPGA主机时序、SPI触发和状态查询、上一帧序号关联、读取/释放缓存、PS DDR保存、UART输出到PC以及逐点固定样本一致性。
使用的是MCU生成的固定自检数据，不是实际雷达回波；没有执行射频采集质量、FFT、目标识别、高速吞吐或长期稳定性测试。不能直接认定真实采集版已经通过。
数据路线是PL SPI主机→AXI GPIO→PS DDR数组→UART，没有经过AXI DMA。与此前接收端看到片选频繁跳变的旧主从版本不同；新版通过不能单独证明旧版片选异常的最终根因。
SPI STATUS结果支持当前四线物理链路可双向通信，不等于独立测量证明板级原理图或Flash网络关系。
