# f1_0 与 V2.9 启动对比检查

检查日期：2026-10-18。仅静态对比和二进制校验，未连接目标板；未改动业务代码或重新生成正式固件。

## 结论

没有发现烧录头、CRC、链接起始地址或启动汇编与旧工程不兼容的证据。确认一处时间单位错误；发现首次 SPI 输出之前存在两次 ADC 完成等待，失败将永久停机，能够造成“没有 SPI 时钟和片选”的现象，但尚不能认定这就是板上故障根因。

## 已核实的相同项

- 两个打包脚本生成镜像的逻辑相同：16 字节头、0x5A 标记、偏移 0x10、SPI 分频 2、CRC32 大端。
- 两个现存镜像的 CRC32 均重新计算通过，头部长度与实际载荷长度一致。当前镜像载荷与当前 raw Bin 逐字节一致。
- 两个 scatter 文件的代码区都是 0x8000 / 64 KiB，RW/ZI 区都是 0x20000000 / 32 KiB。
- 启动汇编 SHA256 完全相同；两个镜像 Reset 向量均为 0x80D1。当前栈顶为 0x20004180，旧为 0x20007BE8，均在 32 KiB 数据区内。
- 排除注释和空白后，共有的 HAL、时钟、电源、GPIO、DMA、SPI、UART、定时器及 ADT2011 驱动代码一致。ADC BSP 将 adcWnpara() 展开为原函数内相同的三个调用，行为等价。
- ADC DMA 长度 512×24=12288，未超过驱动的 16 位计数范围。A/B 共 96 KiB，与链接器管理的 32 KiB RW/ZI 区不重叠。不能仅凭 Keil 的通用 Cortex 内存配置证明目标芯片所有 DMA 跨存储区访问均可用。

## 发现和风险

1. 确认错误：project_config.h:24 将 PROJECT_TIMEBASE_TICK_US 从旧工程的 1000 改为 100，app_timebase.c:28 仍每中断加 1，NowMs() 直接返回此计数。app_main_tasks.c 用它与毫秒周期相加，50 ms 目标实际变成 5 ms 的调度截止时间；若采集和发送超过 5 ms，则没有预期的周期等待。这不直接解释首次完全无输出。

2. 与无 SPI 输出现象有关的路径：main.c 在 AppFrontend_Prime() 成功前不进入循环；Prime 在 app_main_tasks.c:186 等待 A 帧完成；首次 RunCycle 又先等待 B 帧完成，之后才调用 AppSpiStream_Trigger()。任一次 ADC 超时或波束操作失败都会进入 app_fatal_stop() 永久空转，无错误提示。因此“没有 SPI”不能证明 ROM 没启动；当前程序也可能已运行但在首次发送前失败。

3. 采集配置差异：旧工程 16 chirp，当前 24 chirp；旧工程仅固定 ADC 地址，当前 B 缓冲为 0x20014000..0x2001FFFF。首次发送依赖 B 缓冲采集成功。此改变需要针对实际芯片存储区和 DMA 寻址能力核实，尚无越界或硬件访问失败的直接证据。

4. SPI 实现与部分交付说明不一致：AppSpiStream_Trigger() 用 CPU 循环写 FIFO，先等本轮 ADC 完成才发送上一帧。它没有实现说明中的 ADC/SPI 并发 DMA。发完整帧前不读取 RX FIFO，存在接收溢出的处理缺口；尚不能据此断言 TX 完全没有时钟。

5. 观察接口变化：旧工程 UART0 可回包、UART1 上报并打印启动信息；当前 UART0 仅 RX、UART1 未初始化，P0 作为 SPI /CS。串口完全没有打印是当前设计行为，不能单独作为未启动的证据。

6. 硕飞工程文件：两个 SP32 文件内均能看到 Winbond / W25X40CL 字符串，并分别引用对应 _andar_flash.bin 路径。尚未解析其内部烧录范围、校验选项和缓存镜像，不能仅凭路径证明实际写入 Flash 的内容与磁盘 Bin 相同。

## 当前限制

未获得目标 Flash 的读回内容、CPU 停机位置或 DMA 实测计数，因此尚不能在“实际写入不正确”“启动初始化卡住”“首次采集失败”之间确定唯一根因。25 KB 的大小与链接统计一致，但这只证明文件长度自洽，不代表固件已通过硬件验证。
